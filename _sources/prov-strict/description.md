## PROV — strict typing profile

A profile of [`ogc.model.cross-domain.prov`](../prov) that requires every
object-property value that is itself *described* in the graph -- appears as the
subject of at least one triple, blank node or IRI alike -- to carry an explicit
`rdf:type`. A value with no outgoing triples at all (a pure by-reference pointer to
an object described elsewhere) is exempt: this graph could not type it even in
principle, so it is not treated as a failure.

The base PROV block deliberately does not require local typing for by-reference IRI
values at all: in an open-world, linked-data setting the referenced object's type is
often asserted in a different document, and PROV-O's own `rdfs:domain`/`rdfs:range`
axioms already imply it, so demanding a local restatement would reject perfectly
valid PROV data. This profile narrows that back down to a genuinely checkable claim:
if a document goes to the trouble of describing a resource, its PROV type should be
among what it asserts (or what the base block's `entail` transform -- RDFS
entailment against the live PROV-O ontology -- can derive for it); if a document only
*points at* a resource without describing it, no local claim about its type was ever
being made, so none is required.

## SHACL shapes

`shapes.shacl` (this directory) adds one `sh:targetSubjectsOf`-based `PropertyShape`
per PROV-O object property. Each requires `sh:or` between the value having the
expected `sh:class` and the value matching the shared `<#NotDescribedInGraph>` shape
(a `sh:sparql` constraint that holds exactly when a node has no outgoing triples) --
so a described-but-untyped value fails, while an undescribed by-reference value
passes via the second alternative. It does not restate
`ogc.model.cross-domain.prov`'s own node shapes or its class-to-property
associations -- those are inherited automatically at validation time via this
block's `dependsOn`, and continue to apply alongside these (purely additive) shapes.
Generated by `generate-shapes.py` in this directory; see that script's docstring for
the full rationale. Re-run the script rather than hand-editing its output.

Datatype (literal-valued) properties are unaffected by this typing relaxation and are
therefore validated only by the base block's shapes, not repeated here.
