## SHACL shapes

`shapes.shacl` (this directory) is mechanically derived from PROV-O's own
`rdfs:domain`/`rdfs:range` axioms, giving `sh:class`/`sh:datatype` shapes for every
class and property PROV-O defines. Generated by `generate-shapes.py` in this
directory; see that script's docstring for the full rationale (it follows the
conversion rule categories documented by
[sparna-git/owl2shacl](https://github.com/sparna-git/owl2shacl), reimplemented
directly against PROV-O since owl2shacl's own ruleset depends on a TopBraid-only
SPARQL extension function). Re-run the script rather than hand-editing its output.

Object-property values are only `sh:class`-checked when given as a blank node.
A value given as a plain IRI is treated as a by-reference pointer to an object
described elsewhere and is not locally type-checked here -- the type PROV-O's own
axioms imply for it is real, but not something this open-world validation demands
be asserted in the same document. See "Strict typing profile" below for where that
implied typing is actually checked.

## Strict typing profile

[`ogc.model.cross-domain.prov-strict`](../prov-strict) is a profile of this block
that requires `sh:class` for every object-property value that is itself described in
the graph (blank node or IRI alike) -- but not for a value that is a pure by-reference
pointer with no outgoing triples of its own, since this graph could not type it even
in principle. Running this block's `entail` transform (`transforms.yaml`) first makes
that check strictly stronger: RDFS entailment types *every* PROV object-property
value from the property assertion alone, regardless of local description, so a value
that would otherwise only pass via the strict profile's "not described" exemption
ends up genuinely, explicitly typed instead. The transform declares
`ogc.model.cross-domain.prov-strict` as an output profile, so postprocessing
validates every example here, post-entailment, against the strict shapes.
